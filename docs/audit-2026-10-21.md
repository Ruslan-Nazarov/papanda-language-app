## Рефакторинг

- Три экрана используют один механизм перехода карточки вместо трёх копий
  анимации с разными правилами отмены. Порог и направление свайпа каждого
  режима сохранены.
- Правила ручного редактирования предложений вынесены из UI в
  `prepareSentenceEdit` и вызываются на границе записи в store.
- Разрешение переводов и определение выученного слова используют общие
  функции, включая пустые пользовательские значения и текущие языки.
- Выбранное предложение адресуется по ID. Удаление соседей из кеша не
  подменяет карточку, пока она сама остаётся в доступной очереди.

Формат резервной копии, стабильные ключи слов, версии приложения и настройки
провайдеров не изменены. Исходники книги и словарные наборы не менялись.

  **174 теста, 0 ошибок**. Новые проверки покрывают дефекты из таблицы:

  На Windows временный каталог перенесён в `.expo/audit-temp`, поскольку
  Hermes не мог записать байткод во временный каталог песочницы.
- `npm run build --prefix gemini-proxy` — успешный dry run без публикации.
- `benchmark-sentence-validation.ts` — 2608 словарных форм, 83 токена,
  8 карточек: 1,4–5,6 мс в локальном Node; это не замер на телефоне.
- `npm run check:ui` — **все 9 наборов сценариев прошли** на итоговой сборке:
  onboarding, web, workshop, book, review, trainer, generation, word-entry,

  пересечение действий, сохранение замечания ИИ, лимиты туров и немедленный
  ответ на следующую карточку после свайпа.
- Генерация проверена с замедлением CPU в 4 раза: максимальное измеренное
  время переключения вкладки — 280 мс. Отмена поздних ответов и сохранение
  выбранной карточки при вытеснении соседей из кеша прошли проверку.
- `git diff --check` — без ошибок форматирования.
