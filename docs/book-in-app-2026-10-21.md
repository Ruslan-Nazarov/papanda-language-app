## Объяснения живым языком — изменения после build 21

Переработаны инструкции ИИ и окно «Как устроена фраза». Вместо обязательной похвалы, грамматического паспорта каждого слова и отвлечённого заключения основной текст объясняет конкретную фразу: всё сказуемое, затем подлежащее и существенные добавления, с наблюдаемыми признаками форм. Порядок авторского метода сохранён. Длина зависит от сложности, дополнительные примеры не обязательны.

Разбор всех слов, значимых частей и служебных элементов доступен по кнопке «Разобрать слова и окончания». Список книжных источников тоже сначала свёрнут. В тексте запрашивается не более двух ссылок на применённые правила; лишние или выдуманные ссылки вызывают одну попытку исправления с передачей предыдущего ответа. Проверка адресов не заменяет проверки смысла правила.

Живые проверки на английском `She did not come.` и казахском `Қыз ұйықтаған жоқ.` дали ответы 1030 и 1025 знаков, в каждом — два слоя и две ссылки на переданные фрагменты книги. Эти два примера проверяют подачу и доступность источников, а не гарантируют лингвистическую точность всех ответов. Исходники книги не менялись. Обновлённые объяснения включены в build 22.

- Поиск по выбранному разделу или всей книге, переход к найденному фрагменту, оглавление главы, предыдущая/следующая глава, размер шрифта, до 100 закладок и продолжение чтения после перезапуска.

- Из упражнения можно открыть правило для текущего члена предложения и вернуться к тому же шагу. Чтение правила засчитывается как помощь, а не самостоятельный ответ.

- Формат разметки объяснён модели явно: повтор `Predicate` у нескольких слов одной основы обозначает единое составное сказуемое. В подробностях сохраняется порядок от сказуемого к подлежащему.
- Основа предложения показывается первой, раздел «Подробности» раскрывается отдельно, если модель соблюла этот формат. Старые ответы без этого разделения остаются целиком читаемыми.
- При подготовке разметки предложения для мастерской и генератора также передаются выдержки из книги. Независимая проверка разметки сохранена.

## Источники и обновление

Исходные Word-файлы пользователя не изменяются. Источник встроенного текста — Markdown в `book/`. Содержимое всех 66 материалов дополнительно сверено с Word-файлами папки «готово»: после исключения нумерации не обнаружено пропущенных вхождений слов. Это проверка полноты переноса, а не лингвистическая экспертиза.

После правки Markdown выполнить:

```sh
npm run book:build
npm run check
```

Генератор `scripts/build-book.cjs` создаёт `src/data/book.generated.json` без сети и ИИ. Главы и фрагменты имеют проверяемые адреса; SHA-256 каждого исходника включён в данные. `book:check` в общей проверке и CI обнаруживает рассинхронизацию исходника и данных приложения.

Точные адреса фрагментов зависят от их текста: после его изменения устаревшие закладки отбрасываются при загрузке. Данные книги не записываются в основной store и не заменяют словарь, предложения или прогресс обучения. Настройки чтения и закладки хранятся на устройстве отдельно (`papanda-book-reader`); существующий экспорт учебного прогресса их пока не включает.

## Что проверить вечером на телефоне

1. «Настройки → Книга и метод → Открыть книгу»: открыть каждый язык, включая русский и приложение к нему.
2. Включить авиарежим и открыть несколько глав, таблицу глагольных форм и поиск. Сама книга должна оставаться доступной.
3. Найти `did` в английском и `кітап` в казахском; открыть результат, проверить место перехода.
4. Увеличить шрифт, прокрутить главу, сохранить закладку, закрыть и снова открыть приложение. Проверить закладку и «Продолжить».
5. «Мастерская → Самостоятельно → Книга: …»: прочитать правило, вернуться и завершить текущий шаг. Ответ должен учитываться как ответ с помощью.
6. С подключённым интернетом нажать «Объяснить структуру»: проверить основу, раскрытие подробностей, переходы по источникам и отдельное обозначение пояснения ИИ.
7. Из главы другого языка перейти в практику: должны показываться предложения выбранного языка, а возврат должен вести обратно в книгу.
8. Проверить словарь, сохранённые тексты и старую статистику после установки поверх предыдущей версии.

## Ограничения первой версии

- Отдельной главы латыни нет в авторской книге. Для неё доступны общая схема и метод с явной пометкой, что это не правила латыни.
- Книга включает русский, но отдельного русского тренажёра в приложении пока нет.
- Подбор отрывков выполняется локально по ролям и словам/маркерам; он может подобрать общий, а не самый точный фрагмент. Проверка существования ссылки не доказывает правильности применения правила. Дополнительное пояснение не должно приписываться авторскому тексту.
- Оригинальные формулировки книги сохранены; её лингвистическая редактура не входила в эту версию.
- Автоматические браузерные проверки используют ответы ИИ-заглушки и не расходуют квоту. Качество живых ответов и поведение на конкретном Android-устройстве нужно проверить отдельно.

## Автоматические проверки

`npm run check`: актуальность книжных данных, TypeScript приложения и прокси, общий набор тестов.

После экспорта с фиктивным адресом ИИ:

```sh
EXPO_PUBLIC_GEMINI_PROXY_URL=https://smoke.invalid/v1/generate npx expo export --platform all --output-dir dist-audit
BOOK_SMOKE_DIR=dist-audit node scripts/smoke-book.cjs
```

В PowerShell переменные задаются через `$env:EXPO_PUBLIC_GEMINI_PROXY_URL` и `$env:BOOK_SMOKE_DIR`.

`smoke-book.cjs` открывает все 66 материалов на экране шириной 320 пикселей, проверяет поиск и переход к источнику, закладки, перезапуск, шрифт, переход в упражнение и обратно, учёт помощи, раскрытие подробностей ИИ и кликабельную цитату. Внешние запросы перехватываются тестом. Тестовая сборка с `smoke.invalid` не предназначена для установки пользователю; для APK используется профиль EAS preview с настоящими настройками окружения.
